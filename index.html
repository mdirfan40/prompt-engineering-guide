Advanced Prompt Engineering

11 chapters. Zero jargon first. Every concept explained from a real-world story to under-the-hood mechanics — with flow diagrams.

Chapter 1 — Foundation

What is Prompt Engineering?

Learning to talk to an AI so it actually understands what you want.
🍽️ Story first

Imagine you walk into a restaurant. You're hungry. If you just say "food please" — the waiter is confused. But if you say "one plate of Dilli momos, steamed, with green chutney, not too spicy" — you get exactly what you want. The dish (answer) didn't change. The kitchen (LLM) didn't change. Only how you ordered (the prompt) changed. Prompt Engineering is the art of ordering your dish perfectly.

Flow diagram — the prompt pipeline

How it works under the hood

An LLM (Large Language Model) is a giant function: it takes text in → predicts the most likely next tokens → outputs text out. It was trained on billions of web pages, books, and code. It has no memory of your previous chat. Every message you send is a fresh context window.

The model doesn't "understand" you like a human. It does pattern matching at massive scale. Your prompt is the pattern it matches against. A badly written prompt matches a bad pattern → bad output. A well-crafted prompt matches the right pattern → great output.

The 4 parts of a great prompt

📌 Instruction

What you want the model to do. Be specific. "Summarize" vs "Summarize in 3 bullet points for a 10-year-old."

📄 Context

Background information the model needs. The more relevant context, the better the answer.

📥 Input data

The actual content to process — the document, question, or data you want the model to work on.

📤 Output format

Tell it exactly how to respond: JSON, bullet list, one paragraph, formal tone, Hindi, etc.

💡 Key insight

The model is like a brilliant person who just woke up with amnesia every single conversation. Your prompt is the only information it has. Treat it like a complete brief — assume nothing is remembered from before.

Chapter 2 — Technique #1

Zero-Shot Prompting

Just ask. No examples. Trust the model's training.
🎯 Story first

You call a plumber and say: "My kitchen tap is leaking — fix it." You didn't give the plumber an example of what a fixed tap looks like. You just described the problem and trusted their expertise. That's Zero-Shot prompting — you give the model a task and trust it to know how to handle it from its training.

Flow diagram — zero-shot prompting

How it works under the hood

During training, the LLM saw millions of examples of sentiment classification, translation, summarization, and almost every text task. It learned these patterns implicitly. When you do zero-shot, you're activating that latent knowledge with just a description.

The model reads your prompt and asks internally: "What pattern does this match? What text would naturally follow this in my training data?" If the task is common (translation, summarization, Q&A), zero-shot works very well.

# Zero-Shot — just describe the task prompt = """ Translate the following English sentence to Hindi: Sentence: The weather is beautiful today. Translation:""" # The model outputs: "आज मौसम बहुत सुंदर है।"
💡 Key insight

Zero-shot works best when the task is simple, common, and well-defined. For complex reasoning or niche tasks, it needs help — that's when we move to Few-Shot or Chain-of-Thought.

Chapter 3 — Technique #2 (GPT-3 Paper, 2020)

Few-Shot Prompting

Teach by example. Show the model 2–5 examples before your real question.
🏫 Story first

A new intern joins Dilli Bites. You don't hand them a 50-page manual. You say: "Here — this customer asked for 'combo A', I gave them momos + chai. This customer asked for 'special', I gave them garlic bread + chutney. Now this customer is asking for 'light snack' — what do you give?" The intern gets the pattern from 2 examples and answers correctly. That's Few-Shot prompting.

Flow diagram — few-shot vs zero-shot comparison

How it works under the hood

This concept was introduced in the landmark GPT-3 paper (Brown et al., 2020). They discovered something surprising: you don't need to retrain the model. Just including 2–5 examples directly in the prompt is enough to dramatically improve accuracy.

Under the hood, the model uses the examples as an in-context learning signal. It analyzes: "What is the input format? What is the output format? What is the pattern?" Then it applies that pattern to the new question. No gradient updates, no fine-tuning — pure pattern completion.

# Few-Shot — examples teach the pattern prompt = """ Classify sentiment: Review: "The biryani was out of this world!" Sentiment: Positive Review: "Cold food, rude staff. Never again." Sentiment: Negative Review: "It was ok I guess." Sentiment:""" # Output: "Neutral" — The model learned from examples!
💡 Key insight

Few-shot is the most powerful basic technique. For most real-world tasks, showing the model what you want is more reliable than describing it. 2–3 well-chosen examples are often enough. The quality of examples matters more than the quantity.

Chapter 4 — Technique #3 (Wei et al., 2022)

Chain-of-Thought (CoT) Prompting

Make the model show its work, step by step. Reasoning → Answer, not just Answer.
📐 Story first

A student writes "Answer: 47" with no working shown. The teacher says: "Show your steps!" With steps visible, the student catches their own mistake. The same happens with LLMs. When you force the model to write out its reasoning step-by-step before the final answer, it makes far fewer errors. The act of writing the steps actually changes the computation inside the model.

Flow diagram — standard vs chain-of-thought

How it works under the hood

The LLM generates tokens one at a time, left to right. Each token it generates becomes part of the input for the next token. When you force the model to write intermediate steps, those steps become visible "working memory" — the model can attend back to them when computing the next token.

This is why CoT improves reasoning: the model isn't skipping steps internally anymore. The chain of tokens literally extends the computation graph. More tokens written = more compute applied to the problem.

Two flavors of CoT

Few-Shot CoT (Wei et al. 2022)

Include 2–3 worked examples with full reasoning chains in your prompt. Best accuracy. The model mirrors the exact step style from your examples.

Zero-Shot CoT (Kojima et al. 2022)

Just append "Let's think step by step." No examples needed. Surprising finding: this single phrase unlocks reasoning in large models.

# Zero-Shot CoT — the magic phrase prompt = """ Q: Roger has 5 tennis balls. He buys 2 cans of 3 balls each. How many tennis balls does he have now? Let's think step by step.""" # Model output: # "Roger starts with 5 balls. # He buys 2 cans × 3 balls = 6 new balls. # 5 + 6 = 11 total balls. # The answer is 11."
💡 Key insight

Chain-of-Thought only works in large models (100B+ parameters). Small models don't benefit. This is called an "emergent ability" — it appears suddenly at scale, like a phase transition. For everyday tasks, just add "Let's think step by step" to your prompt.

Chapter 4 — Variant (Zhang et al., 2023 · arXiv:2210.03493)

Automatic CoT (Auto-CoT)

The problem with Few-Shot CoT: someone has to write those examples manually. Auto-CoT removes that human effort entirely — it generates its own examples automatically.
🏫 Story first

Imagine you're a teacher preparing exam questions. You have 100 student questions. You don't read all 100 — you group similar ones together (clustering), pick one representative question from each group, solve it step-by-step yourself, and use those solved examples in tomorrow's lesson. Auto-CoT does exactly this — but fully automatically, using the LLM to do the grouping and the solving.

Flow diagram — 2-phase Auto-CoT pipeline (from the IIT KGP slide)

How it works under the hood

Regular Few-Shot CoT needs a human to write 2–5 high-quality reasoning chains. That is expensive, slow, and biased. Auto-CoT (Zhang et al., 2023) automates this in two phases:

Phase 1 — Clustering

All questions are converted to embeddings (vector representations). Then k-means clustering groups similar questions together. Each cluster = one type of reasoning problem.

Phase 2 — Sampling

One representative question is picked from each cluster (the one closest to the centroid). Zero-Shot CoT ("Let's think step by step") is applied to generate its reasoning chain automatically.

The result: k question+reasoning-chain pairs, built with zero human labelling effort. These become the few-shot examples for the final prompt.

# Auto-CoT — pseudocode # Phase 1: Cluster all questions embeddings = embed_model.encode(all_questions) clusters = kmeans(embeddings, k=8) # Phase 2: Sample + auto-generate reasoning demonstrations = [] for cluster in clusters: rep_q = pick_centroid(cluster) # nearest to cluster center zs_cot = rep_q + "\nLet's think step by step." chain = llm.generate(zs_cot) # auto-generates reasoning demonstrations.append((rep_q, chain)) # Final prompt = all demos + new question final_prompt = format_few_shot(demonstrations) + new_question answer = llm.generate(final_prompt)
💡 Key insight

Auto-CoT beats hand-crafted Few-Shot CoT on most benchmarks. The key insight: diversity of examples matters more than quality of individual examples. By clustering, you guarantee each demo covers a different type of reasoning — much better than a human picking examples with unconscious bias.

Chapter 5 — Decoding Parameters

Temperature, Top-K & Top-P

How the model decides which word to write next — and how you can control the randomness.
🎰 Story first

Imagine the LLM is spinning a roulette wheel after each word. Each possible next word has a slot on the wheel. More likely words get bigger slots. Temperature controls whether that wheel is tiny and precise (low temp = always picks the obvious word) or huge and wobbly (high temp = more creative, surprising picks). Top-K removes all slots except the top K candidates. Top-P removes slots until the remaining ones sum to P% of the probability. These knobs are your creative control.

Temperature — the creativity dial

Every possible next word gets a raw score (logit). Temperature divides these scores before the softmax function converts them to probabilities.

Temperature = 0.0–0.3 (Low)

Almost always picks the highest-probability word. Deterministic, precise. Great for: coding, math, factual Q&A. Risk: boring and repetitive.

Temperature = 0.8–1.5 (High)

Flattens the probability distribution. More random picks. Great for: creative writing, brainstorming, poetry. Risk: hallucinations and incoherence.

Top-K — limit the choices

After temperature scaling, only keep the top K words by probability. Set all other words' probability to zero. Then sample from those K words. top_k=50 means the model can only pick from the 50 most likely next words. This prevents it from randomly picking bizarre words even with high temperature.

Top-P (Nucleus Sampling) — smarter filtering

Top-K always picks exactly K words. But what if the top 3 words already have 95% of the probability? Top-P is smarter: keep the minimum set of words whose probabilities add up to P (e.g., top_p=0.9 means keep words until you've accumulated 90% probability mass). This adapts dynamically to the distribution.

💡 Key insight for Self-Consistency (Chapter 6)

High temperature + Top-P sampling means the same prompt will give different outputs each run. This is not a bug — it's the feature that powers Self-Consistency. You can generate multiple diverse reasoning paths for the same question and then vote on the best answer.

Chapter 6 — Technique #4 (Wang et al., 2023)

Self-Consistency

Don't trust one answer. Sample multiple reasoning paths. Vote on the winner.
🩺 Story first

You have a strange symptom. You visit one doctor — they give you a diagnosis. You're not sure. So you visit 5 different doctors. Three of them say "viral infection", one says "stress", one says "allergies". You go with the majority: viral infection. That's Self-Consistency — run the same prompt multiple times with high temperature (different reasoning each time), then take the most common final answer. The wisdom of the crowd beats a single reasoning chain.

Flow diagram — self-consistency

How it works under the hood

Self-Consistency combines two ideas: (1) CoT gives us diverse reasoning paths when temperature > 0, and (2) majority voting over the final answers is more reliable than any single run. The intuition is that correct reasoning paths tend to converge on the same answer, while incorrect paths scatter to different wrong answers.

# Self-Consistency — run 5 times, take majority answers = [] for _ in range(5): response = llm.generate(cot_prompt, temperature=0.7) answer = extract_final_answer(response) answers.append(answer) final = max(set(answers), key=answers.count) # Counter: {11: 4, 8: 1} → Final: 11
💡 Key insight

Self-Consistency can cost 5–20× more in API calls, but it significantly improves accuracy on complex math and reasoning tasks. Use it when the cost of a wrong answer is high. It's like buying insurance: expensive, but worth it when stakes are high.

Chapter 7 — Technique #5 (Yao et al., 2023)

Tree of Thoughts (ToT)

Don't just think in a line. Think in a tree. Explore multiple branches, prune the bad ones, commit to the best path.
♟️ Story first

A chess grandmaster doesn't just play the first move that comes to mind. They think ahead: "If I move here... then they can go there... but what if I go there instead? No, that leads to a bad position. Let me try this other branch..." They explore a mental tree of possibilities before committing. CoT is like a player who just plays the first move. ToT is like the grandmaster — it searches the space of possible reasoning paths.

Flow diagram — tree of thoughts search

How it works under the hood

ToT has 4 components working together: (1) Thought decomposition — break the problem into intermediate steps; (2) Thought generator — the LLM proposes multiple candidate thoughts at each step; (3) State evaluator — the LLM (or a separate model) scores each thought as "promising/sure/impossible"; (4) Search algorithm — BFS or DFS traverses the tree, pruning dead-end branches.

CoT is a single path through the problem. ToT is a systematic search over the space of all possible reasoning paths, guided by an evaluation signal. This is expensive (many LLM calls per problem) but dramatically better on hard tasks like mathematical puzzle-solving.

💡 Key insight

ToT is the right tool when the problem requires exploration and planning — not just recall or calculation. If a human would need to try multiple approaches on a whiteboard before finding the answer, ToT is probably the right framework. For most everyday tasks, CoT + Self-Consistency is sufficient and far cheaper.

Chapter 8 — Technique #6 (Yao et al., 2023)

ReAct: Reasoning + Acting

The LLM doesn't just think — it takes actions (search, run code, call APIs), observes results, and thinks again. This is how AI agents work.
🔍 Story first

A detective doesn't solve a case by sitting in a chair and thinking really hard. They think → act → observe, over and over. "I think the suspect was at the hotel. [ACTION: Check hotel records]. [OBSERVATION: No booking found]. OK, they must have used a different name. [ACTION: Search for aliases]..." That's ReAct. The model thinks (Thought), does something in the real world (Action), reads the result (Observation), then thinks again. This loop continues until the problem is solved.

Flow diagram — the ReAct loop

How it works under the hood

ReAct was introduced in Yao et al. (2023) and demonstrated on HotpotQA (multi-hop questions) and AlfWorld (text game environments). The key insight: interleaving reasoning traces (Thought) with real-world interactions (Action → Observation) reduces hallucination dramatically.

The model's context window grows with each Thought-Action-Observation step. It can look back at previous observations when forming new thoughts. The "Action" step calls a real tool — a search engine, Python interpreter, database query, API. The result is injected back as an "Observation" token sequence. This is literally how all modern AI agents are built (LangChain, AutoGPT, Claude's computer use, GPT-4 plugins).

# ReAct trace example Thought: I need to find the current prime minister of India. Action: Search["Prime Minister of India 2024"] Observation: "Narendra Modi has been Prime Minister since 2014..." Thought: Now I know the answer. Action: Finish["Narendra Modi"]

Why this matters for AI agents

CoT, ToT, and Self-Consistency are "closed-loop" — the model only works with what's in the prompt. ReAct is "open-loop" — it can interact with the real world and get new information at each step. This transforms the LLM from a static text transformer into a dynamic decision-making agent. Everything you've heard about "AI agents" — AutoGPT, Claude's computer use, Cursor AI — is built on this foundation.

💡 Key insight — the paper to read first

Start with the ReAct paper (arXiv:2210.03629) if you only have time for one post-read paper. It's the cleanest explanation of how reasoning and acting combine, and it's the direct ancestor of every AI agent framework used in production today — including what you're building with your LiveKit AI teaching platform.

Chapter 9 — Technique #7 (Zhang, Yuan, Yao et al., 2023 · arXiv:2311.11482)

Meta Prompting

Don't just ask the LLM your question. First ask it: "What is the best way to answer this?" — then use that strategy to get the answer.
🧠 Story first

You have a very hard problem to solve — say, designing the menu for Dilli Bites. You could just start cooking randomly. Or you could first call an expert consultant and ask: "What is the best framework for designing a street-food menu?" The consultant gives you a structure — target audience → price tiers → bestseller anchor → seasonal items. Now you follow that structure to design the menu. You solved it better because you first asked how to think, before thinking. Meta Prompting is exactly this — the LLM first generates the optimal prompting strategy, then uses it to solve the actual problem.

Flow diagram — meta prompting in two passes

How it works under the hood

The paper (Zhang, Yuan, Yao, 2023) calls this a structure-oriented prompting framework. The core idea: for most hard problems, the biggest challenge is not solving the problem — it's figuring out the right structure to approach it. Meta Prompting separates these two concerns into two LLM calls.

Pass 1 — The Meta Pass

You ask the LLM: "What is the best prompting strategy to answer X?" The LLM acts as an expert prompt engineer — it returns a structure, a framework, a step-by-step approach tailored to your task.

Pass 2 — The Solve Pass

You inject the generated strategy back as a system prompt or prefix, then ask the actual question. The LLM now answers using its own designed framework — dramatically better than a naive prompt.

Comparison — naive prompting vs meta prompting

Three flavors of Meta Prompting

Self-Meta

Ask the LLM to generate a prompt for itself: "What prompt would make you answer this best?" Then use that prompt.

Decompose-Meta

Ask the LLM to break a complex task into sub-tasks, each with its own prompt strategy. Solve sub-tasks, then combine.

Persona-Meta

Ask: "What type of expert should answer this and how?" LLM assigns itself a role + method, then answers in that persona.

# Meta Prompting — 2-pass pattern # ── Pass 1: Generate the best strategy ── meta_prompt = """ You are an expert prompt engineer. Task: {user_question} What is the best step-by-step prompting strategy and structure to answer this task accurately? Return ONLY the strategy, not the answer itself. """ strategy = llm.generate(meta_prompt.format( user_question="Design an optimal menu pricing strategy" )) # strategy = "1. Define target segment\n # 2. Anchor with bestseller\n # 3. Build price tiers\n # 4. Apply psychological pricing" # ── Pass 2: Apply the strategy to solve ── solve_prompt = """ Use this framework to answer the question: Framework: {strategy} Question: {user_question} Answer step-by-step following the framework above. """ final_answer = llm.generate(solve_prompt.format( strategy=strategy, user_question="Design an optimal menu pricing strategy" )) # Result: expert-quality, structured answer

When to use Meta Prompting

✅ Use it when

Task is open-ended or complex. You don't know the best structure upfront. Domain is specialized (legal, medical, financial, system design). Quality matters more than speed.

❌ Skip it when

Task is simple and well-defined ("translate this", "summarize in 3 points"). Speed is critical. Cost of 2 API calls matters. Zero-Shot or Few-Shot already works well.

💡 Key insight

Meta Prompting is the AI equivalent of "measure twice, cut once." The first pass is cheap — you're not solving the problem yet, just planning the approach. But that plan dramatically improves the quality of the second pass. Think of it as giving the LLM a thinking scaffold before the thinking itself. This is also the intuition behind why senior engineers write design docs before writing code.

Chapter 10 — Technique #8 (Li, Peng, He et al., NeurIPS 2023 · arXiv:2302.11520)

Directional Stimulus Prompting (DSP)

A small trained model whispers keyword hints to a large frozen model — steering its output without ever touching its weights.
🎙️ Story first

Imagine a brilliant but inflexible chef (ChatGPT). He's a genius but you can't change his recipes — he's set in his ways. Now you hire a smart assistant (a small Policy LM). The assistant reads the customer's order and whispers to the chef: "The customer wants: spicy, quick, vegetarian." Those whispered keywords — the stimulus — steer the chef's output perfectly, without retraining the chef at all. The assistant learns to whisper better hints over time using customer feedback (reward). That's DSP.

Flow diagram — DSP pipeline (matches the IIT KGP slide exactly)

How it works under the hood — 3 components

1. Policy LM (small)

A small, trainable model (T5, GPT-2 small). Its only job: read the input and generate keyword hints — the stimulus. It's small enough to fine-tune cheaply. It never sees the black-box LLM's internals.

2. Black-box LLM (frozen)

A large powerful model (ChatGPT, GPT-4) you cannot retrain. It receives: original article + keyword hints from Policy LM. The hints steer it toward better outputs without touching its weights.

3. Reward signal

The output quality is measured (ROUGE score for summarization, or human thumbs-up). This reward is fed back to train the Policy LM using RL — making its hints progressively better.

Two training phases

Phase 1 — SFT (Supervised Fine-Tuning)

Use pseudo-label data: for each article, automatically extract candidate keywords (e.g., named entities). Train the Policy LM on these as ground-truth hints. This gives it a warm start.

Phase 2 — RL (Reinforcement Learning)

The Policy LM generates hints → Black-box LLM generates output → ROUGE score measured → score becomes the reward signal → Policy LM weights updated to generate better hints. Loop repeats.

Flow diagram — RL training loop for the Policy LM

The key trick — why this is powerful

Most prompting techniques assume you can't change the LLM. DSP agrees — but it trains a separate small model to become an expert hint-whisperer. This gives you the best of both worlds: the raw power of a large frozen model (ChatGPT) + the adaptability of a small fine-tuned model (Policy LM).

In standard Few-Shot or CoT, you manually craft hints. In DSP, the hints are generated automatically and improved via reinforcement learning. The Policy LM gets rewarded when its hints lead to better summaries, and penalised when they don't — exactly like training a dog with treats.

# DSP — simplified pseudocode # ── Phase 1: SFT warm-start ── for article, pseudo_keywords in pseudo_label_data: hints = policy_lm.generate(article) loss = cross_entropy(hints, pseudo_keywords) loss.backward() # standard supervised training # ── Phase 2: RL fine-tuning ── for article in training_data: # Step 1: Policy LM generates keyword hints hints = policy_lm.generate(article) # e.g. "Bob Barker; The Price Is Right; 91" # Step 2: Build prompt for black-box LLM prompt = f""" Article: {article} Keywords to focus on: {hints} Write a concise summary:""" # Step 3: Black-box LLM generates output (no gradients here) summary = blackbox_llm.generate(prompt) # frozen — ChatGPT, GPT-4 etc. # Step 4: Compute reward reward = rouge_score(summary, reference) # or human thumbs-up signal # Step 5: Update Policy LM using RL (REINFORCE / PPO) rl_loss = -reward * log_prob(hints, policy_lm) rl_loss.backward() # only Policy LM weights updated # ── Inference (no training needed) ── hints = policy_lm.generate(new_article) prompt = build_prompt(new_article, hints) output = blackbox_llm.generate(prompt) # ✅ steered by learned hints

DSP vs other techniques

All other techniques (Zero/Few/CoT)

Hints are crafted manually by a human. One-size-fits-all. Static — they don't improve over time. Work at inference time only. No training involved.

DSP

Hints are generated automatically by a trained Policy LM. Input-specific — different hints for every document. Improve via RL as feedback accumulates. Works even when the big LLM is completely locked (API-only).

💡 Key insight

DSP solves a real industry problem: you can't fine-tune GPT-4 (it's locked behind an API). But you can train a tiny model to generate better prompts for it. DSP essentially learns how to talk to a black-box — making it extremely practical for production AI systems where the underlying model is closed-source and inaccessible.

Chapter 11 — Architecture Pattern

Prompt Chaining

Decompose one big task into a sequence of smaller, focused LLM calls. The output of each step feeds directly into the next.
🏭 Story first

Think of a Dilli Bites kitchen. One person takes the order. Another makes the dough. Another stuffs the momos. Another steams them. Another plates them. No single person does everything — each person does one thing perfectly and passes it on. A single super-chef trying to do all steps simultaneously would be slower and make more mistakes. Prompt Chaining is the assembly-line pattern for LLMs — break the big task into specialist steps, and pipe the output of each step into the next.

Flow diagram — prompt chaining pipeline (from the IIT KGP slide)
Real example from the slide — customer review analysis pipeline

How it works under the hood

Every time you call an LLM, it gets a fresh context window — it has no memory of previous calls. Prompt Chaining exploits this by passing outputs explicitly as inputs. Each call is a focused specialist. The chain is essentially a data pipeline where LLMs are the processing nodes.

The critical insight is that a single "do everything" prompt forces the model to juggle too many concerns at once, increasing error. Breaking it into steps means each LLM call is simpler, its output is checkable, and errors in one step are catchable before they cascade to the next.

Two chain topologies

Sequential chain (linear)

Step 1 → Step 2 → Step 3. Output of each step feeds the next. Best for tasks where each step depends on the previous result. Example: translate → summarise → format as JSON.

Parallel + merge chain

Multiple LLM calls run on the same input simultaneously (sentiment + key phrases). Then a final step merges all results. Faster and more thorough. Example: the customer review pipeline above.

# Prompt Chaining — Dilli Bites review analysis reviews = """ Review 1: "Momos were amazing but delivery was slow!" Review 2: "Best garlic bread in Delhi, worth the price." Review 3: "Staff was rude, but the choco lava was great." """ # ── Step 1a: Sentiment Analysis (LLM call #1) ── sentiment_prompt = f""" Classify each review as Positive / Negative / Mixed. Return JSON only. Reviews: {reviews} """ sentiments = llm.generate(sentiment_prompt) # {"r1": "Mixed", "r2": "Positive", "r3": "Mixed"} # ── Step 1b: Key phrase extraction (LLM call #2) ── phrase_prompt = f""" Extract the top 5 key product/service mentions from: {reviews} Return a plain list. """ key_phrases = llm.generate(phrase_prompt) # ["momos", "delivery", "garlic bread", "staff", "choco lava"] # ── Step 2: Combine results (LLM call #3) ── combine_prompt = f""" Sentiments: {sentiments} Key phrases: {key_phrases} Summarise the overall customer experience in 3 bullet points. """ combined = llm.generate(combine_prompt) # ── Step 3: Final formatting (LLM call #4) ── final_prompt = f""" Format this summary as a professional business report section: {combined} """ final_output = llm.generate(final_prompt) # ✅ Polished, structured, accurate report

When to use prompt chaining

✅ Use it when

Task has clean sequential subtasks. Each step's output is verifiable. You want intermediate checkpoints. Task is too complex for a single prompt. Latency budget allows multiple calls.

❌ Skip it when

Task is simple enough for one prompt. Low latency is critical (each chain step adds delay). Steps are not clearly separable. You're paying per API call and budget is tight.

💡 Key insight

Prompt Chaining is the most used architectural pattern in production AI systems. Every serious AI product — Cursor, Perplexity, Claude — uses chaining under the hood. It improves accuracy, traceability, and control. Think of it as the Unix pipe philosophy applied to LLMs: small tools, each doing one thing well, chained together to build powerful workflows. Your Dilli Bites AI assistant and your LiveKit teaching platform are both prompt chains.
